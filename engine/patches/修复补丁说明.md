# GameBox v5.1 渲染修复补丁说明 — v5 GPU 鲁棒选择（闪退根因修复）

## 一、这个补丁修什么

**用户报告**：模拟器启动游戏后闪退打不开，退出码 2147483651（0x80000003）。

**引擎日志证据**（`engine\shadps4\user\logs\shadps4.log` 尾部）：

```
[Render.Vulkan] vk_instance.cpp:106 Instance: Found 2 physical devices
[Render.Vulkan] CollectDeviceParameters: GPU_Model: Intel(R) HD Graphics 530
[Render.Vulkan] CollectDeviceParameters: GPU_Integrated: Yes
[Render.Vulkan] CollectDeviceParameters: GPU_Vulkan_Version: 1.0.50
[Debug] <Critical> vk_instance.cpp:164 Instance: Assertion Failed!
Vulkan 1.3 is required, but only 1.0 is supported by device!
```

**根因链**（引擎源码 `src/video_core/renderer_vulkan/vk_instance.cpp` 逐行实证）：

1. 引擎的**自动选卡**（`gpu_id = -1`）本身是正确的：按
   「支持 Vulkan 1.3 优先 → 独立显卡优先 → 非 CPU → 显存最大」排序，
   GTX 960M（Vulkan 1.4.309，独显）必然排在 Intel HD 530（Vulkan 1.0.50，
   核显）之前。
2. 但**显式编号**（`gpu_id >= 0`）路径没有任何校验：直接取
   `physical_devices[physical_device_index]`，然后断言
   `apiVersion >= 1.3` —— 选到核显 = 立即中止进程（0x80000003）。
3. 前端「圖形裝置」下拉的编号来自 **WMI（Win32_VideoController）枚举顺序**，
   与引擎的 **vkEnumeratePhysicalDevices 顺序**是两套独立体系。旧版前端把
   下拉编号原样写入 `config.json` 的 `Vulkan.gpu_id`：用户在下拉里选
   "1 · GTX 960M"（WMI 顺序里 960M 是 1 号）→ 引擎的 Vulkan 枚举里 1 号
   恰是 Intel HD 530 → 断言 → 闪退。

## 二、补丁内容（1 文件 76 行）

`src/video_core/renderer_vulkan/vk_instance.cpp` 三处加固：

### ① 自动选卡逻辑提取为 `pick_best_device()`（排序规则不变）

原有的排序比较器原样保留（Vulkan 1.3 优先 → 独显 → 非软件渲染 → 显存
最大），只是提取成可复用的 lambda，供下面的回退路径调用。

### ② 显式编号路径：校验 + 自动回退（核心修复）

```cpp
physical_device = physical_devices[physical_device_index];
if (physical_device.getProperties().apiVersion < TargetVulkanApiVersion) {
    // LOG_ERROR（含设备名/编号/版本）+ 回退到 pick_best_device()
}
```

编号指向的卡不支持 Vulkan 1.3 时**不再断言中止**，改为大声记日志并自动
回退到最佳设备。断言仅在「所有设备都不支持 1.3」（真无法运行的机器）时
才会触发。

### ③ 越界钳制

```cpp
} else if (physical_device_index >= static_cast<s32>(num_physical_devices)) {
    // LOG_ERROR + 回退自动选择（原为 ASSERT_MSG 直接中止）
```

编号超出设备数（驱动更新、设备移除、或前端锁定驱动后可见设备数变 1）
→ 回退自动选择而非中止。

### ④ 选卡可见性日志

```
[Render.Vulkan] Using GPU: NVIDIA GeForce GTX 960M (Vulkan 1.4.309)
```

最终选中哪张卡、是否发生过回退，启动日志一眼可查 —— 双显卡笔记本的
选卡问题从此「可验证」而不再靠猜。

## 三、与前端 v5.1 修复的关系（双保险）

| 层 | 修复 | 生效方式 |
|----|------|----------|
| 前端 v5.1 | 编号永不写入（自动=-1 / 指定卡=厂商驱动锁定 VK_LOADER_DRIVER_SELECT）+ 坏编号自愈 + 断言后自动重启 | 解压 GameBox-v5.1.zip 覆盖即生效，**无需重编译** |
| 引擎 v5（本补丁） | 选中的卡不支持 1.3 → 自动回退最佳卡；越界 → 钳制；Using GPU 日志 | GitHub 云编译 / 本机编译后装回 |

两层独立成立：即使只有前端修复（旧引擎 exe），锁定驱动后引擎只看到
960M 一张卡，同样不会崩；即使只有引擎修复（用户绕过前端直跑引擎），
选卡校验也会自动回退到 960M。

## 四、验证

- CI 里补丁应用后有 4 个标记检查（`pick_best_device` / `gpu_fell_back` /
  `Using GPU:` / `is out of range`），任一缺失构建即失败。
- 装回后启动游戏，日志应有 `Using GPU: NVIDIA GeForce GTX 960M`。
- 历史行为回归验证：单显卡机器（只 1 个设备）路径完全不变 —— 自动
  选择仍选唯一设备；显式编号 0 且支持 1.3 时仍按编号选（尊重用户选择）。
