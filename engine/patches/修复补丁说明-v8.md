## 一、v8 渲染返工的三个组成部分

1. 保留（v7 已被实测验证的部分）
   - vk_instance.cpp GetSupportedFormat 全格式回退阶梯：
     D16S8→D24S8→D32S8 / D16→D24S8→D32 / D32→D32S8 深度晋级；
     R8/RG/RGBA/BGRA-sRGB→unorm 兄弟视图回退；
     A2B10G10R10 家族→R16G16B16A16 家族回退。
     依据：582.66 驱动 vulkaninfo 实测——960M 的 D16S8 条目为 NULL
     （DepthStencilAttachment 全缺），D24S8/D32/D32S8 完整支持。
   - vk_graphics_pipeline.cpp 管线深度/颜色格式用纹理缓存的规范特性集
     解析（kDepthImageFeatures / kColorImageFeatures）——管线声明格式
     与图像实际格式永不脱节（深度看穿/贴图重叠的根因之一）。
   - vk_rasterizer.cpp 多边形偏移一次性诊断日志（绿光贴图/贴花排查用）。
   - vk_presenter.h/.cpp 的 ui_view 双视图基建。

2. 撤销（v7 的设计错误，v8 核心）
   - sRGB 帧格式强制直通：v7 把每条 SDR 输出链的帧附件强制换成 sRGB
     兄弟格式。PS4 游戏交出的像素本来已经是显示编码（gamma 已施加），
     再走一次硬件 sRGB 编码 = gamma 双重校正 → 中间调抬高、对比度下降、
     白天发白夜晚发灰（用户 960M 实拍两张截图已归档确认）。
   - v8 恢复原版恒等链：帧附件格式 = 交换链格式（UNORM 直通）。

3. 新增（一个引擎两种亮度）
   - GAMEBOX_OUTPUT_SRGB 环境变量（默认关 = 原版亮度）：
     设 1 时恢复 v7 的 sRGB 输出链。觉得原版太暗想 A/B 对比时，
     前端「sRGB 输出」开关经 gpuLaunchEnv 自动注入，无需重编译。
   - GetFrameAttachmentFormat 以类内静态函数形式定义于 vk_instance.h
     ——根治 v7.0/v7.1 两代"声明顺序"编译失败（定义先于调用点可见）。
