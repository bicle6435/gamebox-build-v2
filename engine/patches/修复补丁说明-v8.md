# GameBox v8.0 引擎渲染补丁说明 —— 亮度返工版

> 版本：v8.0 | 基线：shadPS4-415907b（sifac4k 0.18.1 分支） | 补丁：shadps4-gamebox-v8-render-brightness.patch
> 前置：必须已装 v2→v3→v4→v5→v6（workflow 串行应用，缺一不可）

## 一、本版改了什么（对照 v7）

### 保留的（v7 已验证有效的部分）
| 文件 | 内容 | 960M 能力表实证 |
|---|---|---|
| vk_instance.cpp | 全格式回退阶梯（深度提升 + sRGB→UNORM 兄弟格式 + 10:10:10:2 打包格式改写） | D16S8 条目为 **NULL**，D24S8/D32/D32S8 完整支持 DepthStencilAttachment——阶梯第二级即命中 |
| vk_instance.h | kDepthImageFeatures / kColorImageFeatures 规范特性集 | 保证管线声明格式与图像实际格式永不脱节 |
| vk_graphics_pipeline.cpp | 管线深度/颜色格式用上述特性集解析 | 修复深度看穿/贴花透光的根因之一 |
| vk_rasterizer.cpp | 多边形偏移一次性诊断日志（Polygon offset in use） | 图层重叠/贴花悬浮的第一手证据 |

### 撤销的（v7 的设计错误）
| v7 行为 | 问题 |
|---|---|
| 帧附件强制 sRGB 兄弟格式（eR8G8B8A8Srgb 直通） | 游戏本身已输出显示编码像素 → 硬件再编码一次 = **gamma 双重校正** → 中间调抬高、对比度下降 → **画面发白发灰**（你实测的"越修越亮、还不如原版清晰"） |

### 新增的
1. **GAMEBOX_OUTPUT_SRGB 环境变量**：默认**关闭**（= 原版亮度，清晰优先）。启动前设为 1 时恢复 v7 的 sRGB 输出链。一个引擎两种模式，随时 A/B 对比，不用重新编译。
2. **函数定义移入 vk_instance.h 类内**：彻底规避 v7.0/v7.1 两代的"undeclared identifier"声明顺序编译失败。

## 二、本版不改什么（红线）
- 不动 v2 的 GCN clamp 数学指令补丁（防高光炸裂）
- 不动 v3 的遮挡查询 + 流式输出补丁（防机体隐身）
- 不动 v4 的 Vulkan 默认参数、v5 的 GPU 自动选卡、v6 的缓存防崩
- 不动引擎其它一切行为

## 三、装回步骤（GitHub 网页操作）
1. 仓库根 → Add file → Create new file，逐个上传（复制内容粘贴）：
   - `engine/patches/shadps4-gamebox-v8-render-brightness.patch`
   - `engine/patches/修复补丁说明-v8.md`
   - `engine/patches/装回说明-v8.txt`
2. `.github/workflows/build-patched-engine.yml` → 铅笔编辑 → 整文件覆盖 → Commit
3. Actions → build-patched-engine → Run workflow
4. 约 1~1.5 小时 → 运行页 Artifacts 下载 `shadPS4-415907b-patched-v8`
5. 解压得 `shadPS4-415907b-patched.exe` → 覆盖 `GameBox\engine\shadps4\` 同名文件（旧 exe 建议先改名备份）

## 四、装回后必查清单
1. 启动游戏后打开 `GameBox 文件夹\engine\shadps4\log\shad_log.txt`，应看到：
   - `Host format fallback: D16UnormS8Uint ... using D24UnormS8Uint`（格式阶梯生效）
   - `Polygon offset in use: ...`（多边形偏移日志生效）
2. **亮度 A/B**：默认先玩一局（应恢复原版清晰度）；若觉得太暗，在前端 v8 设置页打开"sRGB 输出"再玩一局对比。
3. 游戏用户目录 `custom_configs/CUSA15006.toml` 里的 `patchShaders` 与 `logEnabled` 若为 false，改回 true（v8 前端体检页会自动提醒）。
