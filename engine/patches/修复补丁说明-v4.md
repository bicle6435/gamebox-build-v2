## 一、v4 修什么（Vulkan 性能优化出厂默认）

应用户要求：**FIFO/Mailbox、独显直连、管线缓存预置** 三项全部设为最高性能/最优化值，
写进引擎出厂默认，不需要任何手动设置。逐项说明（全部对源码实证，非猜测）：

### 1. 管线缓存预置 —— 本次唯一需要改代码的项（真正的引擎层修复）

- 源码实证（emulator_settings.h:481-482）：上游出厂默认
  `pipeline_cache_enabled = false`、`pipeline_cache_archived = false`。
  **管线缓存出厂是关的**——意味着每次启动游戏都全量重编着色器/管线（逐管线编译卡顿），
  编译完也不保存，下次启动全部重来。
- v4 修改：`pipeline_cache_enabled{true}` + `pipeline_cache_archived{true}`。
  首次运行编译并归档管线；之后每次启动 `PipelineCache::WarmUp()` 预载入全部管线
  （启动日志可见 `Preloaded N pipelines`），不再逐管线编译卡顿。
- 归档模式 = 每个游戏的缓存存为**单个 zip 文件**（cache 目录下），整洁、
  备份或预置到别的机器只需拷一个文件。
- 兼容性安全阀（源码实证，WarmUp 内建）：缓存里的着色器档案与本机不兼容时
  自动忽略重建，只打一条日志警告，不会崩溃不会黑屏。

### 2. FIFO/Mailbox 呈现模式 —— 出厂默认本就是最优，v4 只加"可见性"

- 源码实证（emulator_settings.h:432 + vk_swapchain.cpp:192-222）：
  出厂默认 `present_mode = "Mailbox"`。Mailbox = 三重缓冲：不撕裂 + 低呈现延迟，
  弱显卡（如 GTX 960M）的最优选择；驱动不支持时引擎自动回退 Fifo（规范保证可用）。
- v4 附加：去重 INFO 日志 `Present mode: mailbox (requested: Mailbox)`——
  启动日志里直接确认最优模式生效，可见可验证。

### 3. 独显直连 —— 出厂自动选择本就优先独显，无需改代码

- 源码实证（vk_instance.cpp:108-147）：`gpu_id` 出厂默认 -1（自动），自动选择
  排序规则 = ① 支持的目标 Vulkan API 版本 → ② **独立显卡优先（eDiscreteGpu）** →
  ③ 显存最大。Optimus 双显卡笔记本自动选 GTX 960M，不需要写死索引（写死反而脆弱：
  换机器/换驱动顺序变化就失效）。
- 与 GameBox 前端"图形装置"页的手动 GPU 选择（gpuId=1）互为双保险。

### 与 GameBox 前端 migrate40 的关系（诚实说明）

GameBox v4.0 前端自己也有一次性迁移（写 Mailbox + 管线缓存开）。但那依赖
**前端在位且写入成功**。v4 补丁把最优值固化进**引擎出厂默认**：
引擎独立运行、前端写入失败、全新用户目录、config 重建等所有场景下同样生效。
用户 config 文件里已有显式值时照常尊重（前端 migrate40 写的就是这些最优值）。

## 二、v3 修什么（遮挡查询，机体隐形/贴图残影的直接根因）

源码实证：遮挡查询合成计数器 `pixel_counter` 从 0 开始，**第一次 ZpassDone 查询写入
"0 个可见样本"** → 游戏判"完全被遮挡"→ 剔除几何（**机体隐形**）或跳过条件清除
（**贴图残影跟随机体永不消失**）。v3 初始化为 0x2FFFFFF（约 50M），首次查询即"可见"。

另附三条诊断日志（ZpassDone 查询值 / IT_SET_PREDICATION / 绘制瞬间谓词值），
游戏可见性判定链断在哪一环，日志一眼可见。

## 三、装回后验证方法

启动游戏跑一局，看 `GameBox-v4.0\engine\shadps4\user\logs\` 日志，检索：

- `Present mode: ` → v4 呈现模式确认（应为 mailbox）
- `Vulkan PipelineCacheEnabled: 1` → v4 管线缓存默认开
- `Preloaded N pipelines` → 第二次启动起出现 = 管线缓存预载入生效
- `D16S8 depth format fallback (D24S8) detected: depth-bias units rescaled` → v2 深度补偿生效
- `Occlusion query (ZpassDone) synthesized` → v3 遮挡查询生效
- `Conditional rendering active: predicate value` → 条件渲染生效 + 谓词实时值

游戏内观察点：机体是否还隐形、贴图残影是否还跟随不消失、第二次启动是否明显更快进入流畅状态。

## 四、已知限制（不隐瞒）

1. 管线缓存首次运行仍需完整编译一遍（这是建立缓存的必然成本，从第二次启动开始受益）
2. v3 的遮挡查询值是"合成可见"策略（模拟器业界通行，RPCS3 同类）：游戏的遮挡剔除
   优化失效，可能轻微增加渲染量（GTX 960M 极端情况可能略降帧率，正确性优先）
3. 缓存与本机绑定（着色器档案校验）：换显卡/换驱动后首次运行自动重建，属正常
4. D16S8 硬件级支持不可能（NVIDIA 无此格式），v2 回退精度补偿已是上限
5. 着色器翻译器体量巨大，v2 修复的是实证缺口族，不等于"翻译器完美"
