# GameBox v7.0 渲染根治补丁说明 — D16S8 格式阶梯 + 管线一致性 + sRGB 输出链

> **v7.2 修订（2026-10-07）**：修复 v7.1 的第二次云编译失败。
> 错误：`vk_presenter.cpp(502): function declared in block scope cannot have 'static' storage class` +
> `(561): use of undeclared identifier 'GetFrameAttachmentFormat'`
> 原因：v7.1 的 5 行前置声明被插进了 Presenter 构造函数【函数体内】（块作用域）。
> C++ 规定：①块作用域函数声明不得带 static；②块作用域声明对其他函数
> （RecreateFrame）不可见。
> 修复：废弃前置声明方案，把 GetFrameAttachmentFormat 的定义（含完整注释块）
> 整体搬迁到文件作用域——构造函数之前、与文件内现存 static 辅助函数
> （FitImage/GetFrameViewFormat/PqToNits 等）同层级，定义先于两处调用。
> **新增验证（v7.1 轮缺失的一环）**：从修复树逐字提取定义与调用点，
> 套类型桩用真实编译器 g++ -std=c++23 编译——v7.2 结构零警告通过；
> v7.1 错误结构同法编译，复现出与 CI 日志完全一致的两类错误。
> 另完成：干净树 v2→v6→v7.2 全栈重放 + CI 同款 git apply 双轨验证
> （结果树逐字节一致）+ 6 个 grep 标记命中。**重跑 Run workflow 即可。**

> **v7.1 修订（2026-10-07，已被 v7.2 取代）**：修复首次云编译失败。
> 错误：`vk_presenter.cpp(502/556): error: use of undeclared identifier 'GetFrameAttachmentFormat'`
> 原因：`GetFrameAttachmentFormat` 的定义放在文件后部（PrepareFrame 之前），
> 而调用在前部（Presenter 构造函数）——C++ 要求「先声明后使用」。
> 当时修复：在第一个调用点之前插入 5 行前置声明（后经 v7.2 轮实证：
> 该声明误插入函数体内，方案被 v7.2 取代）。

## 一、这个补丁修什么

**用户报告的三类问题**（原版与 v6 引擎上均存在，纯视觉层、不影响进度）：

| 症状 | 根因（引擎源码逐行实证） |
|------|--------------------------|
| 地图透明化、机体图层上总有地图贴图重叠 | 深度链格式不一致（见②）+ 格式回退缺口（见①） |
| 白天场景发白、夜晚地图透明感 | sRGB 输出链断裂——线性光丢失再编码（见③） |
| 绿光投射光照贴图常显、随机体移动明显 | 深度测试被①②损坏（投射贴图靠深度测试裁剪）；另加诊断日志（见④） |

**用户日志实证**（user.zip 解析）：GTX 960M + Vulkan 1.4.312 驱动上
`D16UnormS8Uint` 缺 DepthStencilAttachment 支持、`A2B10G10R10 / R8Srgb`
等格式特性不完整 —— Maxwell 家驱动的格式支持面比 AMD/RDNA 窄。

## 二、补丁内容（1 个补丁文件，6 个源文件，344 行）

> 补丁基于 v2~v6 全部补丁叠加后的源码生成（CI 按 v2→v3→v4→v5→v6→v7 顺序
> 应用），完整补丁栈已在 Linux 逐级验证全部干净应用；v2 的 D16S8→D24S8
> 深度偏移 ×256 换算（db_format_actual 链）原样保留，v7 与其协同。

### ① 宿主格式回退阶梯补全 — `vk_instance.cpp` `GetSupportedFormat()`

**旧代码的洞**：整个函数的 switch 只处理 `D16S8→D24S8→D32S8` 和
`R8Srgb→R8Unorm` 两组回退；**其余所有格式命中 `default: break`，原样返回
一个设备不支持的格式**——不报警、不打日志，静默把坏格式送进图像/管线/视图
创建，深度测试和颜色附件渲染随之损坏。

**v7 修复**：
- 深度族：`D16S8→D24S8→D32S8`（原有）+ `D16→D24S8→D32S8→D32F`（新增）+
  `D32F→D32FS8`（新增）。宽格式只增加精度，提升安全。
- sRGB 视图族：`R8G8B8A8Srgb / B8G8R8A8Srgb / A8B8G8R8SrgbPack32 / R8G8Srgb
  → 各自的 Unorm 兄弟`（新增；sRGB/UNORM 视图互转是规范允许的）。
- 10:10:10:2 打包色：`A2B10G10R10Snorm/Sscaled→RGBA16Snorm`、
  `Sint→RGBA16Sint`、`Uint/Uscaled→RGBA16Uint`（新增；Maxwell 缺部分
  附件组合，16 位每通道保持数值域与符号性）。
- **回退全可见**：命中回退打 `LOG_INFO "Host format fallback: ..."`；
  无安全替身时打 `LOG_WARNING`（旧代码完全静默）。

### ② 管线深度/颜色格式一致性 — `vk_graphics_pipeline.cpp` + `vk_instance.h`

**旧代码的洞**（本次最重要的发现）：管线声明附件格式时只查
`eDepthStencilAttachment` / `eColorAttachment` 单一旗标，而纹理缓存建同一
张图时用的是**完整旗标集**（附件+采样+传输）。在 D16S8「部分支持」的驱动
（正是 960M 的情形：支持附件写入、缺其它特性组合）上，两边回退决策**不一致**：
图像被建成 D24S8、管线却声明 D16S8 → 动态渲染管线的声明格式与实际附件格式
不匹配 → **深度测试静默损坏** → 该被挡住的地图/机体/贴花没被挡住。

**v7 修复**：`vk_instance.h` 新增 `kDepthImageFeatures / kColorImageFeatures`
两个规范特性集常量（与 `image.cpp` 建图旗标一字不差对齐），管线侧两处查询
改用同一常量——管线格式与图像格式**永不失步**。

### ③ sRGB 输出链补全（A8B8G8R8Srgb 输出链 / 色调映射）— `vk_presenter.cpp/.h`

**旧代码的洞**（发白的数学闭环）：
```
游戏视频输出缓冲(注册为 A8B8G8R8Srgb)
   → 采样视图 sRGB（硬件解码为线性光）          [解码 ✓]
   → FSR / 后处理（线性域运算，正确）            [线性 ✓]
   → 写入 frame 图像 = 交换链 UNORM 格式（原样存）[★ 丢失再编码]
   → 显示器按 sRGB 解释线性字节（≈ v^0.92 曲线）
   → 中间调被整体抬亮 → 白天发白发灰、夜晚发灰透明感
```

**v7 修复**：新增 `GetFrameAttachmentFormat()`——SDR 交换链（RGBA8/BGRA8
UNORM）的 frame 图像改用 **sRGB 兄弟格式**，后处理写入时硬件自动再编码；
`Frame` 新增 `ui_view`（UNORM 视图）供 ImGui 采样——按规范 sRGB/UNORM 对
可安全互转（图像本就带 mutable-format 旗标）——UI 直通原始编码字节，
交换链原样接收 → **整条链 gamma 恒等**。HDR 路径（A2R10G10B10Bt2020Pq）
不受影响，原样保留。

### ④ 多边形偏移诊断日志 — `vk_rasterizer.cpp`

绿光贴图类贴花问题的剩余变体通常是「GCN 偏移寄存器翻译在特定驱动上的单位
差异」。v7 在 `UpdateDepthBias` 首次启用时打印完整寄存器组
（front_scale/front_offset/back_scale/back_offset/clamp），后续任何用户日志
都能一眼对上，诊断有据可依。（偏移换算本身维持与上游一致的翻译——
三份独立仓库（本源码/sifac4k main/官方 master）均未改动该换算，
无实证不冒险。）

## 三、验证方法（装回后 1 分钟）

1. 启动游戏，主界面日志滚动时看两条新日志：
   - `Host format fallback: ... using ... instead`（960M 上应出现
     D16UnormS8Uint → D24UnormS8Uint 一行或数行）= ①生效
   - `Polygon offset in use: front_scale=... `（进对战场景后）= ④生效
2. **白天场景**：整体不再发白发灰，颜色饱和度恢复 = ③生效
3. **地图/机体图层**：重叠与透明显著减少或消失；绿光投射贴图只出现在
   被照亮面上、不再常显 = ①②生效
4. 若仍有残留：把 `user/logs/shadps4.log`（含 v7 新日志）发上来即可定位

## 四、与其他补丁的关系

- v2（GCN clamp/条件渲染/流式输出）、v3（遮挡查询）、v4（Vulkan 默认值）、
  v5（GPU 选卡）、v6（缓存防崩）全部保留不动——v7 是纯叠加。
- **联网（ShadNet）/键位（改建）零接触**：v7 只动 `video_core/renderer_vulkan`
  渲染路径，`src/shadnet/`、`src/core/libraries/np/`、输入/键位、前端联网页
  一行未改。
